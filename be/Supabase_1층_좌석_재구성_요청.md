# Supabase 담당자에게 — Inthon 1층 좌석 48석 재구성 요청

안녕하세요. 실제 링크로 입장 테스트를 해 보니 **1층 좌석이 76석 중 22석만 화면에 보입니다.** 프론트 1층 지도가 Senspace 레퍼런스 레이아웃(48석)으로 그려지는데, DB의 1층 좌석은 실제 도면 기준 76석이라 라벨이 겹치는 24석만 표시되기 때문입니다. 프론트 지도를 바꾸지 않고, **DB 1층 좌석을 프론트 레이아웃과 같은 48석으로 재구성**하고자 합니다.

기존 마이그레이션(001~006)은 **다시 실행하지 말아 주세요.** 새 마이그레이션(예: `007_floor1_seats_48.sql`)로 넣어 주시면 됩니다. (2층 요청 `Supabase_2층_좌석_적용_요청.md`와는 별개이며, 이 요청은 **1층만** 바꿉니다.)

## 0. 회사 / 현재 상태

- 회사: Inthon, `company_id = ff484ad2-375d-416e-86fa-95e01f2b1323`
- 현재 1층(`floor_number = 1`): `map_width 4938`, `map_height 2868`, 좌석 **76석**
  - `A-01…A-16`(16), `B-01…B-04`(4), `C-01…C-04`(4), `D~H` 각 8석(40), `I-01…I-12`(12)
- 프론트 1층 지도: 내장 레이아웃(1400×800), 좌석 **48석** — `A-01…A-16`, `B-01…B-16`, `C-01…C-16`
- 증상: 두 집합이 겹치는 `A 16 + B 4 + C 4 = 24석`만 표시되고, 그중 사용 중인 좌석을 빼면 **22석**만 보입니다. `D~I` 52석은 프론트 지도에 그릴 자리가 없습니다.

## 1. 프론트가 하는 일 (계약)

1. 좌석 매칭은 **라벨만** 씁니다. 프론트는 DB 라벨 `A-01`을 지도 좌석 id `A-1`로 정규화해 비교합니다(`-0` 제거, 대문자).
2. 좌석 좌표(`x_ratio`, `y_ratio`)는 현재 렌더링에 쓰지 않고, `get_employee_location` 등 좌표 기반 응답과의 정합성을 위해 저장합니다.
3. 좌석 선택/저장은 기존과 동일하게 `choose_seat` RPC를 호출합니다.
4. 라벨은 회사 전체에서 고유해야 합니다(`2층 J/K/L`과 겹치지 않음).

## 2. 필요한 변경

### 2-1. 1층 좌석 48석으로 교체

- 48석 이외의 1층 좌석(`D~I`, `B-05` 이후, `C-05` 이후, `A-17` 이상 등)은 삭제합니다.
- 남기는 48석은 라벨 기준으로 좌표를 갱신하고, `B-05…B-16`, `C-05…C-16` 24석은 새로 넣습니다.
- **좌석이 사라지는 직원은 `seat_id`를 NULL로 비워** 주세요. 다음 입장 때 프론트가 좌석 선택 단계로 안내합니다.
- 1층에 좌석이 배정된 직원이 있으면 모두 다시 골라야 합니다(전 좌석을 지우고 다시 넣는 방식이라 `seat_id`를 1층 전체에 대해 먼저 비웁니다).

### 2-2. 동작 확인

- `choose_seat`로 1층 좌석(`A-01`, `B-16`, `C-16` 등) 배정 성공 / 중복·타사 좌석 거부
- 좌석이 비워진 직원이 다시 입장하면 좌석 없음 상태로 조회되고, 프론트가 좌석 선택 단계를 띄우는지 확인
- `get_sensory_cards` / `get_my_membership` 응답의 `seat.floor_number = 1`, 라벨이 `A-01` 형식으로 유지되는지 확인

## 3. 주의 사항

- **1층에 이미 앉아 있는 직원이 있다면 모두 좌석을 다시 골라야 합니다.** (좌석 행을 지우고 새로 넣기 때문) 실제 운영 중이라면 알려 주세요 — 기존 배정을 유지하는 방식(라벨 기준 upsert만)으로 바꿔 드리겠습니다.
- 2층(`floor_number = 2`, `J/K/L` 93석)은 이 요청에서 건드리지 않습니다.
- `floors.map_width/map_height`를 1400×800으로 바꾸는 것은 좌표 의미를 프론트 레이아웃과 맞추기 위함입니다. 2층은 현재 1713×918 그대로입니다.

## 4. 적용 후 확인 체크리스트

- [ ] 1층 좌석이 정확히 **48석** (`A-01…A-16`, `B-01…B-16`, `C-01…C-16`)
- [ ] 1층 `map_width = 1400`, `map_height = 800`
- [ ] `D~I` 등 삭제된 좌석을 쓰던 직원의 `seat_id`가 NULL
- [ ] `choose_seat`로 1층 좌석 배정 성공
- [ ] 실제 링크로 입장 시 1층 지도에 48석이 모두 표시되는지 (프론트에서 확인)

확인용 쿼리:

```sql
SELECT f.floor_number, f.map_width, f.map_height, count(s.id) AS seats
FROM public.floors f
LEFT JOIN public.seats s ON s.floor_id = f.id
WHERE f.company_id = 'ff484ad2-375d-416e-86fa-95e01f2b1323'
GROUP BY f.floor_number, f.map_width, f.map_height
ORDER BY f.floor_number;
-- 기대값: 1 → 1400×800, 48석 / 2 → 1713×918, 93석
```

```sql
SELECT split_part(s.label, '-', 1) AS row, count(*)
FROM public.seats s
JOIN public.floors f ON f.id = s.floor_id
WHERE f.company_id = 'ff484ad2-375d-416e-86fa-95e01f2b1323'
  AND f.floor_number = 1
GROUP BY 1 ORDER BY 1;
-- 기대값: A 16, B 16, C 16
```

## 5. 요청 요약

1. 위 SQL(한 트랜잭션)로 **1층 좌석을 48석으로 재구성**
2. 1층 `map_width/map_height`를 **1400×800**으로 변경
3. 좌석이 사라진 직원의 `seat_id`를 NULL로 비우고, 재입장 시 좌석 선택이 뜨는지 확인
4. 적용 결과(좌석 수, 지워진 배정 수)를 회신해 주시면 프론트에서 실제 링크로 검증하겠습니다.

프론트는 publishable(anon) 키만 사용하고, 위 작업에는 service_role이 필요합니다. 키는 대화/문서에 남기지 말아 주세요.
