# P2 범위와 기존 구현 중복 검토

작성일: 2026-11-01. 최신 상태: 사용자 요청으로 [006 이동·복귀·자유 사유](./자리이동_복귀_API.md)를 구현하고 로컬 검증했다. 이후 사용자가 Supabase 적용·설치 확인 성공을 확인했다. 실제 직원 세션과 FE 통합 검증은 남아 있다. 기본/자유 사유는 둘 중 하나만 사용한다. 팀 영역은 동료와 공유하지 않아 BE 저장을 추가하지 않는다. 공간·집계 연결·새 FE 나머지는 FE 확정 후 결정한다. 최신 계산 규칙은 [감각 집계 최종안](./감각_집계_최종안.md)을 따른다. 아래는 설계 진행 기록이며 이동 미구현을 언급한 부분은 006 이전 시점이다.

## 1. 이번 작업의 해석

이미 구현된 기반은 재사용해 중복 개발에서 제외하고, 현재 없는 P2 동작을 추가한다. 기존 P1 기능을 삭제한다는 뜻으로 해석하지 않는다. 사용자가 원한 제외 범위가 다르면 먼저 정정한다.

현재 상태는 저장소 코드·SQL·명세서와 사용자 확인한 Supabase 적용 기록으로 대조했다. 원격 프로젝트를 직접 조회한 것은 아니다. FE는 현재 localStorage 데모라 실제 데이터 통합 완료와도 구별한다.

## 2. 겹치는 부분과 재사용 범위

| P2 요구 | 기존 구현 | 중복 개발에서 제외할 것 | 새로 필요한 것 |
|---|---|---|---|
| 회사 → 층 | companies, floors, 회사별 RLS | 회사 격리·층 번호·지도 경로·이미지 크기 | 층 이름. 현재 floors에는 층 이름 컬럼이 없음 |
| 층 → 공간 → 자리 | seats는 현재 층에 직접 연결 | 좌석 ID·이름·좌표·중복 배정 방지 | 공간 계층 및 기존 76석의 공간 소속 연결 |
| 공간 이름·유형·영역·정원·고정 특성 | 없음. teams는 조직이고 공간이 아님 | 없음 | 공간 저장·조회·운영 등록 계약 |
| 감각 항목 | 개인 현재 감각 6개·1~5·NULL 의미·입력 API | 개인 감각 필드와 입력 검증 | 시간 가중 평균·응답 수·입력 시각. 계산 모듈은 구현, 공간/관측 조회 연결은 남음 |

| 감각 버튼 | 청각·후각·온도·습도 4개 FE 버튼 | 기존 4개 버튼의 선택/표시 구조 | 혼잡도 버튼과 공간별 집계 응답 연결 |
| 연속 히트맵 | fe/src/heatmap.js의 개인 좌석값 보간 | 색상 함수·범례·렌더링 코드 중 재사용 가능한 부분 | 공간 영역과 집계값 기준 표시. 현재는 공간 평균이 아님 |
| 공간 카드 | 직원 카드 API·UI | 카드 UI 일부 패턴 | 공간 기본 정보·고정 특성·현재 인원·정원·이동 버튼 |
| 자리 이동 | choose_seat는 배정 좌석 자체 변경 | 기존 좌석 배정 규칙은 유지 | 임시 현재 위치·공간 이동·복귀·원래 자리 투명 표시 |
| 층 선택·공간 확대 | 층 선택·지도 확대 UI 있음 | 층 선택·확대 UI 일부 | 공간 선택과 영역 중심 확대, 계층 위치명 |
| 알림 | notifications·본인 읽음 처리·본인 좌석 변경 알림 | 알림함·읽음 구조는 재사용 후보 | 즐겨찾기 관계, 대상 상태/메시지 변경 이벤트, 개인 설정, 브라우저 권한·전달 경로 |

회사·층·좌석 기반은 P1에서도 필요하므로 P2와 겹친다는 이유로 삭제하지 않는다. P1 혼잡도 입력도 이미 확정된 6개 감각 중 하나이므로 유지한다. 기존 회사·지도·좌석·캐릭터 데이터 재생성은 필요하지 않다.

## 3. 현재 기능을 P2 완료로 볼 수 없는 이유

- **배정 좌석과 임시 위치:** 현재 employees.seat_id는 배정된 좌석이다. 이를 회의실 이동에 그대로 사용하면 원래 좌석 유지·복귀 위치를 표현할 수 없다.
- **공간 인원과 좌석 배정 인원:** 현재 좌석 점유는 퇴근해도 유지된다. 이를 공간의 현재 인원으로 세면 퇴근자까지 실제 재실 인원처럼 표시된다.
- **갱신 시각:** current_sensations.updated_at은 6개 항목이 공유한다. 일부 감각 하나만 수정해도 시각이 바뀌므로 나머지 항목의 실제 입력 시각까지 갱신된 것으로 해석하면 안 된다. 최신 최종안은 고정 1시간 만료 대신 항목별 입력 시각의 지수 감쇠를 사용한다.
- **이동 전 감각:** 다른 공간에서 입력한 값을 새 공간으로 그대로 집계하면 공간 특성이 잘못 표시될 수 있다. 입력 장소 연결 또는 초기화 정책이 필요하다.
- **불쾌 지수:** 초기 P2의 온습도 자동 계산 구상은 이후 집계 최종안에서 적용하지 않는다. 6개 개인 감각 입력을 각자 지정 반감기로 가중 평균한다.
- **인원 수와 응답 수:** 공간에 있는 사람 수와 각 감각에 답한 사람 수는 다르다. NULL은 무응답이므로 항목별 응답 수가 달라질 수 있다.
- **브라우저 알림:** DB 알림함이나 5초 재조회만으로 운영체제 브라우저 알림이 자동 표시되지는 않는다. 탭이 열려 있을 때만 알릴지 닫혀 있어도 알릴지에 따라 구현 범위가 달라진다.

## 4. 구현 전 결정 목록

아래는 확정/미정을 표시하며, 미정은 한 번에 모두 결정하지 않고 순서대로 구체화한다.

1. **이동 모델 — 확정:** 배정 좌석은 유지하고 별도 현재 목적지 좌석으로 캐릭터를 이동한다. 원래 위치에는 중간 투명도의 캐릭터를 남긴다.
2. **이동·복귀·근태 관계 — 일부 확정:** 자리 선택으로 이동하면 자동 자리비움(away), 복귀하면 출근(working). 새 '자리이동' 사유는 추가하지 않으며 기존 기본 사유 외 자유 작성 사유를 지원한다. 자유 사유는 최대 20자의 선택 입력이고 없으면 아이콘만 표시한다. 퇴근하면 임시 목적지 캐릭터를 제거하고 원래 좌석만 아주 투명하게 표시하며 다음 출근은 원래 좌석에서 시작한다. 같은 회사의 다른 층으로 이동할 수 있고 복귀 시 원래 층의 배정 좌석으로 돌아간다.
3. **공간 구획 — 초기 범위 확정:** 실제 정보관 1층은 우선 하나의 업무 공간으로 시작한다. 여러 방/공간으로 처음부터 나누지 않는다. 공간 이름·정원·고정 특성·영역의 구체 값은 추가 구체화한다. 이후 FE 연동에서 마우스 드래그로 팀을 설정하는 기능이 필요하며, 드래그 대상과 팀 설정의 의미는 확인 후 설계한다.
4. **이동 대상 — 확정:** 사용자가 목적지 자리를 선택한다. 다른 직원에게 배정되지 않았고 현재 다른 직원이 임시 사용 중이지 않은 자리만 이동 대상으로 허용한다. 원래 배정 좌석은 이동/퇴근 중에도 다른 직원에게 개방하지 않는다.
5. **인원/집계 대상 — 일부 확정:** 이동으로 자리비움 상태인 직원도 현재 목적지 공간의 인원과 해당 공간에서 입력한 감각의 집계 대상이다. 미입력은 인원에만 포함, 감각 응답에서는 제외한다. 퇴근자와 원래 자리 잔상은 현재 인원/응답자로 세지 않는다. 목적지 선택 없는 기본 자리비움의 위치 처리는 추가 결정한다.
6. **이동·복귀·출근 후 감각 — 확정:** 현재 감각 6개 모두 NULL로 초기화한다. 사용자가 해당 위치에서 입력한 항목만 개인 값·공간 집계에 반영한다. 평소 민감도·설명은 유지한다.
7. **집계 — 최종안 확정:** 직원별·같은 공간·같은 항목의 최신 유효 입력 하나에 항목별 시간 감쇠와 고정 30분 구간 응답 수의 제곱근 보정을 적용한다. 고정 시간 만료는 없고 근무일/퇴근/이동 초기화 범위는 분리한다. 세부는 감각 집계 최종안 참조.
8. **불쾌 지수 — 최종안 반영:** 별도 온습도 산식 없이 기존 입력을 2시간 반감기로 같은 가중 평균 계산한다. 새로운 자동 산식은 추가하지 않는다.
9. **수용 인원:** 단순 안내값인지, 정원 초과 이동을 서버에서 막을지. 동시 이동의 정원 판정 필요 여부.
10. **히트맵:** 공간 전체를 평균에 따라 단색으로 칠할지, 공간 안/사이 그라데이션도 필요한지. 무응답 공간·적은 응답 수·온습도 양끝 색상.
11. **알림:** 즐겨찾기 공개 범위, 출근/퇴근/자리 비움/메시지/이모티콘 중 구독할 사건, 본인별 설정. 브라우저 탭 종료 후 전달도 필요한지, 알림 중복·빈번한 변경 묶음.
12. **기존 본인 좌석 변경 알림:** P2 알림과 별개로 유지할지. 이미 적용된 004의 알림을 임의로 삭제/중지하지 않는다.

## 5. 사용자 확정 — 이동·복귀·투명도

- 이동해도 기존 배정 좌석은 유지한다.
- 목적지 **자리**를 선택하면 해당 자리로 현재 캐릭터가 이동한다. 공간 선택만으로 위치가 정해지는 모델로 만들지 않는다.
- 원래 위치에는 적당히 투명한 캐릭터를 유지한다.
- 퇴근한 캐릭터는 이동/자리 비움보다 훨씬 투명하게 표시한다. 같은 투명도를 재사용하지 않는다.
- 향후 제공할 FE 왼쪽 아래 내 정보의 자리비움 상태 버튼은 자리 이동 중 **복귀** 버튼으로 바뀐다.
- 복귀하면 배정 좌석의 캐릭터를 다시 선명하게 표시하는 앞선 요구를 유지한다.
- 자리 이동 시 근태를 자동으로 자리비움(away)으로 변경한다.
- 복귀 시 근태를 자동으로 출근(working)으로 변경한다.
- '자리이동'이라는 새 기본 자리비움 사유는 추가하지 않는다.
- 기존 기본 사유 외에 자리비움 사유를 자유롭게 작성할 수 있게 한다. 작성한 사유는 자리비움 아이콘 옆에 표시하며 기본 맵과 내 정보 창에 같은 값을 사용한다.
- 자유 사유 입력은 선택 사항이다. 입력하지 않아도 이동 및 자동 자리비움 전환이 가능하며 이 경우 자리비움 아이콘만 표시한다. 입력하면 표시 가능한 배율의 맵 및 내 정보 창에서 아이콘 옆에 사유를 표시한다.
- 자유 자리비움 사유는 최대 20자다. 기존 상태 메시지와 별도 데이터이며 두 항목의 20자 제한도 각각 적용한다. 글자 수 기준은 기존 메시지와 일관되게 적용하도록 후속 명세에서 정의한다.
- 복귀하거나 퇴근하면 자리비움 사유를 자동 초기화한다. 기본 사유와 자유 사유 모두 지난 사유가 다음 이동에 남지 않도록 한다. 기존 상태 메시지는 별도 규칙을 유지하며 복귀만으로 삭제하지 않고 퇴근 시 삭제한다.
- 이동 중 퇴근하면 임시 목적지 캐릭터를 제거하고 원래 배정 좌석에만 아주 투명한 캐릭터를 표시한다. 다음 출근은 원래 배정 좌석에서 시작한다. 임시 목적지는 퇴근 시 더 이상 현재 위치/인원으로 남지 않는다.
- 목적지는 다른 직원의 배정 좌석이 아니며 다른 직원이 임시 사용 중인 좌석도 아니어야 한다. 상대가 자리비움/이동/퇴근 상태라도 그 사람의 배정 좌석에는 이동할 수 없다. 원래 자리의 잔상은 예약을 유지하는 표시다.
- 같은 목적지 좌석을 동시에 선택한 직원 둘이 모두 이동 완료되는 일이 없도록 서버에서 원자적으로 점유를 판정해야 한다. 실패하면 이전 위치·근태·사유가 함께 유지되도록 설계한다.
- 같은 회사 안에서는 다른 층의 선택 가능한 좌석으로 이동할 수 있다. 복귀 시 원래 층의 배정 좌석으로 돌아간다. 회사 경계를 넘는 이동은 허용하지 않는다.
- 연속 이동 시 원래 배정 좌석의 중간 투명도 잔상만 유지하고 이전 임시 목적지의 캐릭터·점유는 해제한다. 현재 목적지 한 곳에만 실제 위치 캐릭터가 존재한다. 새 목적지 이동이 실패하면 이전 임시 목적지는 계속 유지한다.
- 퇴근(off_work) 중에는 자리 이동을 차단한다. 출근(working) 후 이동할 수 있고, 이미 이동 중인 자리비움(away) 상태에서는 다른 목적지로 재이동할 수 있다. 이동 요청이 자동 출근을 대신하지 않는다.
- 목적지 자리 이동·연속 재이동·원래 자리 복귀 시 현재 감각 6개를 모두 DB NULL로 초기화한다. 출근 직후에도 6개는 모두 NULL이며 사용자 입력을 받기 전에는 감각 값으로 표시·집계하지 않는다. 위치 변경과 근태·감각 초기화는 함께 성공하거나 함께 취소되도록 설계한다.

| 상황 | 배정 좌석 | 목적지 좌석 | 내 정보 버튼 |
|---|---|---|---|
| 본래 자리에서 근무 | 선명한 캐릭터 | 별도 이동 캐릭터 없음 | 기존 자리비움 관련 버튼 |
| 자리 이동/자리 비움 | 중간 투명도 잔상 유지 | 현재 캐릭터 위치 | 복귀 버튼 |
| 복귀 완료 | 다시 선명하게 표시 | 이동 캐릭터 제거 | 기존 버튼으로 복원 |
| 퇴근 | 이동 때보다 훨씬 투명 | 이동 캐릭터 제거, 현재 인원에서 제외 | 출근 UI. 다음 출근은 원래 좌석 |

구체적인 opacity 숫자는 아직 정하지 않았다. DB status의 이동→away·복귀→working은 확정됐으며 기본 사유·자유 사유의 저장 규칙과 나머지 전이 예외는 추가 결정한다. 위치 이동과 해당 근태 변경은 함께 성공하거나 함께 취소되어야 한다.

백엔드는 배정 좌석과 현재 위치·이동 상태를 분리해 FE가 잔상과 현재 캐릭터를 구별할 수 있어야 한다. 투명 캐릭터를 추가 직원/현재 인원/감각 응답자로 중복 집계하지 않는다. 구체적인 저장 컬럼·API는 나머지 정책 확정 뒤 작성한다.

기본/자유 사유는 후속 사용자 결정으로 상호 배제하며 006에 구현했다. 아직 미정인 것은 목적지 선택 없는 기본 자리비움의 위치·집계 처리다. 숫자 투명도와 이후 제공될 FE의 구체적인 버튼 배치는 FE 연결 단계에서 확인한다.

### 사용자 확정 — NULL과 응답 반영

- 현재 감각 6개는 temperature/humidity/noise/odor/crowd/discomfort의 기존 개인 체감 항목이다. 초기화는 각 저장값을 NULL로 바꾸는 것이며 0·3·빈 문자열로 저장하지 않는다.
- 실제 출근 전환 직후, 자리 이동, 연속 재이동, 복귀 직후에는 6개 모두 NULL이다. 평소 민감도·설명은 지우지 않는다. 퇴근 시 감각 NULL 처리도 기존 규칙을 유지한다.
- 사용자가 값을 입력한 시점부터 그 항목만 표시·집계한다. 예를 들어 소음만 입력하면 소음 응답만 존재하고 나머지 항목은 NULL/무응답을 유지한다.
- NULL은 평균 계산과 해당 항목 응답 수에서 제외한다. 한 명의 입력을 6개 항목 전체 응답으로 세지 않는다.
- 유효 응답이 0개인 항목은 평균도 NULL이며 응답 수는 0이다. 지도에는 미입력/데이터 없음으로 표시하고, 보통·조용함·쾌적함 등의 실제 수치 색상으로 치환하지 않는다.
- 현재 공간 인원과 감각 응답 수는 별개다. 이동으로 자리비움 상태가 된 직원은 현재 목적지 공간 인원에 포함하며, 감각을 입력하지 않았으면 인원에만 포함한다. 해당 공간에서 입력한 항목부터 감각 집계에 반영한다.
- 원래 배정 좌석의 투명 잔상은 인원·감각 응답자로 포함하지 않는다. 퇴근한 직원도 공간 현재 인원·집계에서 제외한다. 목적지 선택 없는 점심/미팅/외근의 위치와 집계는 별도 결정한다.
- FE의 슬라이더가 화면상 중간 위치를 기본으로 그리더라도 그것을 자동 저장·전송해서는 안 된다. 실제 사용자 입력 전에는 NULL 의미를 유지한다.
- 불쾌 지수도 최신 사용자 최종안의 시간 가중 평균을 적용한다. 입력이 없으면 NULL이며, 개인 불쾌지수에 임의 온습도 자동 산식을 추가하지 않는다.
- 집계에는 직원별·항목별 마지막 입력값 하나만 사용한다. 같은 직원이 소음을 3→5로 변경하면 5점 응답 1개다. 현재 마지막 값이 NULL이면 이전 입력을 대신 사용하지 않는다.
- 고정 시간 제한은 두지 않는다. 항목별 마지막 실제 입력 시각에 지수 감쇠를 적용하되 새로운 입력/유효 대상 변경 없이 시간 경과만으로 점수는 변하지 않는다. 다른 항목 수정으로 시각을 갱신하지 않는다. 기존 1시간 제안은 채택하지 않았다.
- 시간 가중 평균/30분 집중 보정 외의 재확인·환경 변화 알림·신뢰도·의견 불일치 기능은 이번 집계 구현 범위에서 제외한다. 앞선 P2 즐겨찾기 브라우저 알림 설계도 이번 계산 작업에서 구현하지 않는다.

### 자유 사유와 확대·축소 표시 분석

사용자는 일정 배율 이상 확대하면 메시지를 표시하고 축소하면 아이콘만 남기고 메시지를 숨기는 방식을 제시했다. 이번 요청은 책임 범위 분석이며 확대/축소 기능 구현 지시는 아니다.

| 항목 | 담당 | 근거 |
|---|---|---|
| 현재 줌 배율·메시지 표시 임계값 | FE | 각 사용자의 현재 지도 화면에만 필요한 표시 상태 |
| 확대 시 아이콘과 텍스트, 축소 시 아이콘만 표시 | FE | 이미 받은 데이터를 화면에서 선택해 표시. 데이터 삭제/저장 요청이 아님 |
| 자유 자리비움 사유 입력 UI·맵/내 정보 렌더링 | FE | 입력·텍스트 배치·기본 사유와의 선택 UI |
| 자유 사유의 저장·검증·본인 수정·회사별 공유 | BE | 재로그인/동료/다른 기기에서도 같은 현재 상태를 읽어야 함 |
| 근태·기본 사유·자유 사유·독립 이모티콘·상태 메시지 제공 | BE | 공통 조회 응답. 확대 배율마다 다른 API를 만들 필요 없음 |

현재 away_reason은 lunch/meeting/outside만 허용한다. 자유 사유를 임의로 그 필드에 전달하면 DB CHECK와 RPC에서 거부된다. 자유 사유를 별도로 저장하도록 모델과 API를 확장해야 하며, 20자 status_message에 덮어써 두 의미를 합치지 않는다. 구체적인 컬럼/인자 이름과 제약은 정책 확정 뒤 정한다.

맵과 내 정보 창은 동일한 사유 데이터를 사용하되, 지도 줌에 따른 텍스트 숨김 규칙을 상세 정보 창에도 적용할지는 별개다. 상세 창까지 자동으로 숨긴다고 가정하지 않는다. 자리비움 아이콘과 빠른 상태 이모티콘의 표현을 FE에서 연결할 때 기존 독립 상태 계약을 유지한다.

줌 수치·텍스트 표시 여부를 직원의 공용 DB 상태로 저장하지 않는다. 축소는 화면에서 텍스트를 숨기는 것이므로 BE의 사유/메시지를 초기화하지 않는다. FE는 최신 상태를 기존 조회/갱신 흐름으로 받고, 확대할 때마다 재조회할 필요는 없다. 대규모 지도 전송 최적화는 추후 성능 문제가 확인될 때 별도 검토한다.

이번 단계에서는 확대·축소 코드, CSS 표시 구현, SQL/마이그레이션을 작성하지 않았다.

### 초기 공간과 향후 팀 설정

- 초기 공간 구성: 정보관 1층을 하나의 업무 공간으로 시작한다. 현재 등록된 76개 좌석의 공간 소속을 이 초기 업무 공간으로 연결하는 방향이다. 아직 DB 연결 변경은 하지 않았다.
- 후속 사용자 확정: 드래그 팀 영역은 동료와 공유하지 않는다. 영역 그리기·개인 표시 설정은 FE에서 처리하며 이번 BE에 저장 기능을 만들지 않는다. 조직 소속 team_id와 감각 집계 공간을 변경하는 동작도 추가하지 않는다.
- 추후 FE에서 마우스 드래그로 팀을 설정하는 기능이 필요하다. 지금 이 기능을 구현한 것은 아니며 현재 단계에서는 확장 요구를 기록한다.
- '팀 설정'이 지도 영역/좌석의 팀 구역 지정인지, 직원 소속 팀 일괄 지정인지 아직 확정되지 않았다. 의미를 확인하기 전에 팀 영역·직원 소속 변경을 같은 동작으로 묶지 않는다.
- 기존 teams/employee.team_id는 조직 소속을 표현하고 P2 공간은 실제 위치·인원·감각 집계 범위다. 단일 업무 공간 안에 여러 팀이 생길 수도 있으므로 조직 팀과 공간의 개념을 분리해 설계한다. 향후 드래그 설정에 필요한 좌표·권한·API 범위는 해당 의미 확정 후 정한다.

## 6. 재사용 후 추가할 P2 작업 묶음

1. 공간과 좌석 소속·현재 위치·복귀 모델 구체화.
2. 개인 감각의 장소·항목별 시각과 공간 집계 규칙 구체화.
3. 공간 카드·다섯 감각 버튼·영역 확대의 API와 FE 계약 설계.
4. 즐겨찾기·이벤트 구독·브라우저 알림 범위 설계.
5. 결정 결과를 문서로 확정한 뒤 후속 SQL·API·권한·FE 연결·테스트 작성.

기존 P1의 회원가입/회사 가입·캐릭터·20자 메시지·독립 이모티콘·개인 감각·근태 API는 재사용한다. P1의 FE 실제 연결·사용자 세션 통합 검증이 아직 남아 있다는 사실도 P2 설계와 함께 관리한다. OpenAI 캐릭터 생성 보류 결정은 그대로 유지한다.

## 7. 이번 단계의 변경 범위

초기에는 이 문서만 작성했고, 이후 사용자 최종안에 따라 BE 집계 계산 모듈과 테스트·연결 명세만 추가했다. P2용 SQL, 기존 SQL 수정, DB 변경, FE 기능 변경, 확대·축소 구현, 추가 알림, 커밋·푸시는 이번 계산 작업에서 수행하지 않았다. 나머지 미정 사항은 결정 전 구현하지 않는다.
