# Senspace — 감각이 다른 동료가 함께 일하는 사무실

감각 민감도(소리·빛·냄새·온도·혼잡도)가 사람마다 다르다는 점에서 출발한 **픽셀 오피스 협업 서비스**입니다.
동료의 지금 상태와 감각 정보를 한 화면에서 확인하고, 서로 배려할 수 있는 자리·공간·시간을 고를 수 있게 합니다.

| 항목 | 내용 |
| --- | --- |
| 서비스명 | **Senspace** (감각 배려 오피스) |
| 배포 주소 | https://teletubbies-omega.vercel.app |
| 체험(로그인 없이) | https://teletubbies-omega.vercel.app/demo |
| 심사용 개인 링크 | 아래 **[심사 접속 링크](#심사-접속-링크)** 표 (20~30개) |
| 기술 스택 | React 18 · Vite 5 · Supabase(Postgres · Auth · Edge Functions) · Vercel |
| 저장소 구조 | `fe/` 프론트엔드 · `be/` DB 스키마/문서 · `landing/` 서비스 소개 페이지 |

---

## 1. 왜 만들었나

사무실은 모두에게 같은 공간이지만, 모두에게 같은 공간은 아닙니다.
예민한 사람은 **옆자리 통화 소리**, **형광등**, **누군가의 향수** 때문에 하루의 집중을 잃습니다.
그런데 지금의 협업 도구는 "회의 중/자리 비움"만 알려 줄 뿐, **그 사람이 지금 어떤 감각적 상태인지**는 알려 주지 않습니다.

Senspace는 이 정보를 **지도 위에 올립니다.**
누가 어디에 있고, 지금 소리·빛·냄새·온도를 어떻게 느끼는지, 어디가 조용한지 한눈에 보이게 합니다.

## 2. 핵심 기능

| 기능 | 설명 | 화면 |
| --- | --- | --- |
| **픽셀 오피스 지도** | 1F/2F 도면 위에 동료 캐릭터가 실제 좌석에 앉습니다. 확대·축소, 방(회의실·탕비실) 들어가기, 층 전환이 됩니다. | `/office` |
| **상태 말풍선** | 출근·자리 비움·퇴근 상태와 상태 메시지가 캐릭터 위 말풍선으로 표시됩니다. 축소하면 아이콘만, 확대하면 문장 전체가 보입니다. | `/office` |
| **감각 카드** | 동료마다 지금의 소음·온도·습도·냄새·혼잡도와 민감도를 카드로 확인합니다. | `/office` → 동료 카드 |
| **감각 지도(히트맵)** | 층 전체의 감각 분포를 항목별 색으로 보여 줍니다. "어디가 조용한가"를 색으로 판단할 수 있습니다. | `/office` 우측 하단 |
| **내 팀 영역 설정** | 지도에서 드래그해 우리 팀 구역을 지정하고, 지정한 구역으로 바로 확대합니다. **설정 해제**로 언제든 원래대로 되돌릴 수 있습니다. | `/office` 지도 좌측 상단 |
| **캐릭터 꾸미기** | 머리·눈·옷과 **피부 톤**을 골라 나를 닮은 픽셀 캐릭터를 만듭니다. 설정은 계정에 저장되어 지도에 바로 반영됩니다. | `/character` |
| **AI 예약 비서** | 자연어로 "내일 3시 회의실 잡아 줘"처럼 요청하면, 서버가 빈 시간을 확인해 예약을 도와줍니다. | `/office` → AI 비서 |
| **반응형 화면** | 창을 줄이면 지도·동료 목록·카드가 세로로 쌓이고, 이름·감각 카드가 겹치지 않게 재배치됩니다. | 모든 화면 |

## 3. 심사 접속 링크

심사위원분들은 **각자에게 발급된 개인 링크**로 바로 입장할 수 있습니다.
링크를 열면 로그인 없이 해당 사용자 계정으로 들어가고, 그대로 `/office`로 이동합니다.

## 4. 화면 살펴보기

1. **입장** — 개인 링크로 들어오면 첫 화면에서 좌석을 고르고 감각 민감도를 설정합니다.
2. **사무실(`/office`)** — 지도에서 나와 동료의 위치·상태를 확인하고, 아래 카드에서 내 상태와 감각을 바로 바꿉니다.
3. **프로필(`/profile`)** — 이름·직책·자리·감각 소개를 수정합니다.
4. **캐릭터(`/character`)** — 캐릭터를 꾸미면 지도에 즉시 반영됩니다.
5. **AI 비서** — 지도 위 AI 비서 버튼에서 자연어로 예약을 요청합니다.

## 5. 기술 구성

```
┌───────────────────────────┐        ┌──────────────────────────────┐
│  fe/  React 18 + Vite 5   │  HTTPS │  Supabase                    │
│  · 사무실 지도(픽셀 렌더)   │ ─────► │  · Postgres + RLS            │
│  · 감각 카드 / 히트맵       │        │  · Auth(익명·이메일)          │
│  · 캐릭터 스프라이트 생성   │        │  · Edge Function(LLM 비서)    │
└───────────────────────────┘        └──────────────────────────────┘
                 Vercel (Root Directory: fe) — SPA rewrite
```

- **지도 렌더링**: 도면 좌표계(1400×800) 위에 좌석·가구·캐릭터를 절대 배치하고, 카메라(줌·팬)로 뷰포트에 맞춥니다.
- **캐릭터**: 18×28 픽셀 캔버스를 코드로 그려 PNG 데이터 URL로 변환합니다. 스프라이트 캐시로 재렌더를 줄였습니다.
- **백엔드**: 테이블·RLS·RPC로 권한을 서버에서 강제합니다. 프론트에는 **publishable(anon) 키만** 들어갑니다.
- **AI 비서**: Supabase Edge Function이 로그인 세션을 검증한 뒤 LLM을 호출합니다. API 키는 서버 시크릿에만 있습니다.

### 폴더 구조

```
fe/    프론트엔드(Vite + React)
  src/react/         화면(OfficePage, ProfilePage, ReferenceViews …)
  src/senspace.js    지도·좌석·팀 영역·캐릭터 편집 로직
  src/api.js         Supabase 어댑터(데모 모드도 같은 인터페이스)
  src/sprites.js     픽셀 캐릭터 생성기
  public/            런타임 이미지(아이콘·가구·타일)
  tests/             Node 테스트
be/    DB 마이그레이션 SQL과 설계/연동 문서
landing/  서비스 소개 페이지
```

## 6. 로컬에서 실행

```sh
cd fe
npm ci
npm run dev      # http://localhost:5173  (/demo 로 체험 모드 입장)
npm test         # 28개 테스트
npm run build    # 프로덕션 빌드
```

`fe/.env.local`에 다음 두 값이 필요합니다(실제 키는 저장소에 커밋하지 않습니다).

```sh
VITE_SUPABASE_URL=...
VITE_SUPABASE_PUBLISHABLE_KEY=...
```

## 7. 테스트

`npm test`는 좌석 배치, 카드/팝업 이동, 팀 영역 드래그·저장, 캐릭터 저장, 온보딩, 알림 설정, 아이콘 자산 경로를 검증합니다.
테스트는 메모리 저장소만 사용하며 실제 사용자 데이터를 바꾸지 않습니다.

## 8. 보안·개인정보 원칙

- 프론트엔드에는 **publishable 키만** 사용합니다. `service_role`/시크릿 키는 코드·저장소·로그 어디에도 두지 않습니다.
- 좌석·상태·감각 정보의 접근 제어는 **DB의 RLS와 RPC**에서 결정합니다.
- LLM API 키는 Edge Function 시크릿에만 있고, 호출은 로그인 세션 검증 후에만 허용됩니다.
- 개인 초대 링크는 재사용 가능하지만 계정 단위로 귀속되며, 링크 자체에는 비밀번호가 없습니다.
