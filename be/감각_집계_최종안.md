# Sensory Fit — 감각 데이터 집계 최종안 반영

기준: 사용자가 제공한 「감각 데이터 집계 알고리즘 최종안」. 기존 P2의 평균·기간·불쾌 지수 관련 초안보다 이 최종안을 우선한다.

구현: [sensory-aggregation.mjs](./aggregation/sensory-aggregation.mjs).
검증: [sensory-aggregation.test.mjs](./tests/sensory-aggregation.test.mjs), Node 22에서 24개 테스트 통과.

## 1. 구현 범위와 현재 상태

계산 모듈은 아래 세 단계만 수행한다.

1. 현재 회사·공간·근무 범위에 해당하는 직원별·항목별 최신 유효 입력 선택.
2. 시간 감쇠 및 같은 고정 시간 구간의 응답 집중 보정 가중치 계산.
3. 공간별·항목별 정규화 가중 평균 산출.

외부 패키지·네트워크 호출·타이머·상태 자동 갱신이 없는 BE용 ES 모듈이다. 재확인 기능, 환경 변화 감지/알림, 신뢰도, 의견 불일치, 추가 브라우저 알림, 확대·축소는 구현하지 않았다.

현재 Supabase 001~005에는 공간/현재 위치·근무 구간·항목별 실제 입력 시각 데이터가 아직 없다. 이 모듈은 그 정보를 정규화한 BE 조회 결과를 입력받는 계산 계층이며, 실제 Supabase 쿼리/RPC/마이그레이션에 연결된 상태는 아니다. 종전의 SQL 작성 보류를 유지해 이번 작업에서 SQL과 기존 DB·FE 코드를 변경하지 않았다. 공간·이동 모델이 구체화되면 조회 계층을 연결한다.

## 2. 최종 계산 규칙

항목 d의 직원 i 입력값을 x_i, 실제 입력 시각을 t_i로 두면:

```text
time_weight_i = 2 ^ (-(t - t_i) / half_life_d)
weight_i      = time_weight_i / sqrt(valid_respondents_in_fixed_bucket_i)
score_d       = sum(weight_i * x_i) / sum(weight_i)
```

| 기존 DB 항목 | 감각 | 반감기 |
|---|---|---|
| noise_level | 소음 | 2시간 |
| odor_level | 냄새 | 3시간 |
| temperature_level | 온도 | 4시간 |
| humidity_level | 습도 | 4시간 |
| discomfort_level | 불쾌 지수 | 2시간 |
| crowd_level | 혼잡도 | 2시간 |

고정 구간 기본값은 30분이다. Unix epoch UTC 기준으로 :00~:29:59… / :30~:59:59…를 나누며, 한국 표준시의 :00/:30 경계와도 일치한다. 이동하는 최근 30분 창이 아니다. 구간별 유효 응답자 수는 **동일 회사·공간·항목의 최신 유효 입력을 선별하고 NULL을 제외한 뒤** 센다.

같은 직원의 이전 입력·중복 조회 행·다른 공간/항목·퇴근자·현재 근무 범위가 아닌 입력은 구간 인원을 늘리지 않는다. 최신값이 NULL이면 예전 숫자 입력을 대신 사용하지 않는다.

불쾌 지수도 지정한 2시간 반감기로 같은 가중 평균을 계산한다. 이번 최종안에서는 기존 P2 초안의 온습도 기반 자동 산식을 별도로 추가하지 않는다. 온도·습도는 기존 1~5 양방향 체감 척도를 그대로 평균한다. 실제 섭씨·습도 %로 바꾸거나 임의 환경값을 추정하지 않는다.

응답이 없으면 score=null, response_count=0, last_input_at=null이다. 점수를 0·3 등으로 대체하지 않는다. 점수는 계산 후에도 실수 그대로 반환하며 FE가 표시할 때 반올림한다.

## 3. 시간만 지나서는 점수가 변하지 않는 이유

입력·유효 대상·설정이 동일하면, 같은 항목의 모든 시간 가중치는 시간이 지날 때 동일한 배율로 줄어든다. 해당 배율은 분자·분모에서 상쇄된다. 따라서 정규화 점수는 시간만 지났다고 바뀌지 않는다.

코드에서는 각 항목의 마지막 유효 입력 시각을 계산 기준점으로 사용한다. 원래 수식과 같은 점수이며, 시간이 많이 지난 입력만 있을 때 모든 가중치가 0으로 계산되는 수치 문제를 방지한다. 로그 가중치를 공통 배율로 정규화하고 합산할 때 부동소수점 오차를 줄인다. 시간에 따른 임의 보정이나 타이머 갱신은 없다.

새로운 실제 입력이 추가·변경되면 같은 함수로 다시 계산한다. 퇴근·이동·복귀·NULL 초기화·근무 범위 변경으로 유효 집합이 바뀔 때도 해당 현재 유효 집합을 사용한다. 이는 시간 경과만으로 환경이 변했다고 추정하는 것과 다르다. 설정 상수를 명시적으로 변경한 경우에는 새 설정에 따른 점수가 나올 수 있다.

예시: 오전 9시 소음 2점 10명 + 오후 1시 소음 5점 1명 → **3.6754446796632414**, FE 2자리 표시는 **3.68**이다.

## 4. BE 조회 계층과의 입력 계약

아래 필드는 **계산 모듈의 입력 형식**이며 지금 DB에 이미 존재하는 컬럼이라는 뜻이 아니다. FE가 만든 임의 목록을 권한 확인 없이 넣지 않는다. RLS 또는 본인/회사 권한을 확인한 BE 조회 결과를 일관된 스냅샷으로 전달한다.

### 호출 범위

| 입력 | 의미 |
|---|---|
| companyId | 조회 권한이 있는 회사 ID |
| spaceId | 한 번 계산할 공간 ID |
| workdayId | BE가 판정한 현재 근무일/관측 범위 식별자 |
| asOf | 권한/위치/관측 데이터를 조회한 스냅샷 기준 시각. 시간대 포함 ISO 또는 Date |
| presence | 직원별 실제 현재 위치·근태·관측 범위 |
| observations | 항목별 관측 기록. 이미 최신 행만 조회했거나 여러 입력 기록을 전달할 수 있음 |

### presence 행

```text
company_id, space_id, employee_id,
workday_id, work_session_id, observation_epoch_id,
epoch_started_at, status
```

- status는 working/away/off_work다. 이동으로 away인 직원도 현재 목적지에서 포함한다. 투명 잔상은 별도 presence로 전달하지 않는다. 퇴근자는 제외한다.
- work_session_id는 출근부터 퇴근까지의 **근무 구간**이다. 로그인이나 Auth 세션 ID가 아니다. 같은 날 재출근해도 이전 근무 입력을 재사용하지 않는다.
- observation_epoch_id는 출근·이동·복귀 등 감각 NULL 초기화 후의 현재 관측 구간이다. 같은 방에 재방문해도 예전 방문의 입력이 되살아나지 않게 구분한다.
- workdayId/workday_id는 현재 근무일 범위가 일치해야 한다. 야간 근무의 근무일 경계 등은 향후 BE 근태 정책에서 정하며 이 모듈이 브라우저 날짜로 임의 추정하지 않는다.
- epoch_started_at은 현재 관측 구간 시작이다. 그 이전 관측은 잘못 섞이지 않도록 제외한다.

### observations 행

```text
company_id, space_id, employee_id,
workday_id, work_session_id, observation_epoch_id,
dimension, value, observed_at, revision
```

- dimension은 기존 DB 감각 키 6개 중 하나다. value는 1~5 정수 또는 명시적 NULL이다.
- observed_at은 해당 항목이 실제로 변경/입력된 서버 시각이다. 다른 항목 수정, 카드 재조회, 상태 메시지 변경, 주기적 polling 때문에 갱신하지 않는다.
- 기존 current_sensations.updated_at은 6개가 공유하는 행 수정 시각이므로 **그대로 6개 항목의 observed_at에 복사하면 안 된다.** 향후 기록 계층은 항목별 입력 시각을 보존하고 동일 값 재전송으로 갱신하지 않도록 해야 한다. 현재 계산 모듈 자체는 입력값·시각을 수정하지 않는다.
- revision은 시각이 같은 입력의 선후를 판정하는 BE의 단조 증가 정수다. 64비트 정밀도를 보존하려면 십진 문자열로 전달한다. 최신 시각, 같은 시각이면 높은 revision을 선택한다.
- NULL 삭제가 최신 기록이면 해당 직원/항목은 제외하고 예전 값으로 돌아가지 않는다. 초기화 후 관측이 아예 없으면 빈 관측 목록으로도 표현할 수 있다.
- asOf 이후의 미래 관측과 현재 관측 구간 이전 값은 제외한다. 잘못된 현재 유효 입력값·애매한 시각·동일 관측 버전의 충돌은 명시적으로 오류 처리하며 새로운 데이터로 추정하지 않는다.

## 5. 호출 및 반환

```js
import { aggregateSpaceSensations } from './aggregation/sensory-aggregation.mjs';

const result = aggregateSpaceSensations({
  companyId, spaceId, workdayId, asOf,
  presence: currentPresenceRows,
  observations: sensoryObservationRows,
});
```

반환 형식:

```text
{
  company_id, space_id, workday_id,
  sensations: {
    temperature_level: { score, response_count, last_input_at },
    humidity_level:    { score, response_count, last_input_at },
    noise_level:       { score, response_count, last_input_at },
    odor_level:        { score, response_count, last_input_at },
    discomfort_level:  { score, response_count, last_input_at },
    crowd_level:       { score, response_count, last_input_at }
  }
}
```

response_count는 가중 응답 수가 아니라 유효한 서로 다른 직원 수다. 공간의 현재 전체 인원은 별도 기존 P2 위치 정보이며 감각 응답 수와 혼용하지 않는다. last_input_at은 해당 항목의 마지막 유효 실제 입력 시각이지 조회할 때의 현재 시각이 아니다. 신뢰도·의견 불일치·환경 변화 등의 추가 출력은 없다.

상수는 DEFAULT_AGGREGATION_CONFIG에 있고 호출 시 bucketMinutes와 halfLivesHours 일부를 덮어쓸 수 있다. 설정 UI나 DB 설정 관리 API는 추가하지 않았다.

## 6. 검증

```text
node --test be/tests/sensory-aggregation.test.mjs
```

24개 테스트 통과: 제시한 3.68 예시, 반감기 6개, 고정 구간 경계, 최신 입력과 NULL, 중복 응답 제거, 공간/회사/항목 분리, 시간 경과 불변, 새로운 입력 반영, 근무일/재출근/재방문 격리, away의 목적지 반영, 시간대, 오래된 입력과 수치 안정성, 상수 변경, 64비트 버전, 잘못된 입력 등이다.

이 결과는 계산 로직의 검증이다. 실제 Supabase의 공간/항목별 입력 기록/근무 구간 조회와 연결된 통합 검증 결과로 확대하지 않는다.
